# 开发原则

> 本文档为最高指令，绝不允许修改。所有开发行为必须遵守以下规则。

## 项目信息
- 项目名称：四人专属网页联机游戏室
- 技术栈：原生 HTML/CSS/JS + Node.js + Express + Socket.IO
- 后端：单一 server.js 文件
- 前端：public/ 目录下多个独立 HTML 页面，无框架
- 状态管理：后端用 Map 对象存储全部状态，前端用 sessionStorage 传递身份

## 开发流程

1. 每次修改/开发之前，都应当先阅读 Dev/Technology.md 了解需要的技术细节。
2. 在每次进行开发之后，都应当将所有修改的必要技术细节写入 Dev/Technology.md 中。必要细节指的是对接时需要文档指导的技术内容，比如重要后端返回规则、数据结构、Socket事件等所有代码技术细节。
3. 当任何行为（包括写代码/修改文件/用户的指令等），只要和原则/要求对立/矛盾，先不做修改，先询问等到回复完整后再进行行为。
4. 每次写代码/改代码之后，都应该将此次修改的大意写入文档 Dev/log.md，该文档明确写明本次修改的版本号（如 0.1、0.2）、修改的文件、每个被修改文件的修改原因。本文档用于日志调查。
5. 如果用户反馈错误，需要仔细排查问题并修改。将错误信息、解决办法、如何避免完整解释并写入 Dev/error.md 文件。每一次修改代码之前必须阅读 error.md 文档并避免文档中提到的错误内容。
6. 每次出现错误都将在此文档中展示并要求修复，每次错误都有专属错误编码号（如 A000、A001 等），在对话框中使用该编码定位错误信息在本文档中的位置。
8. Dev/Technology.md、Dev/log.md、Dev/error.md 由 AI 助手编辑，在开发开始之后，自动创建并持续编辑。
9. good.md文档中为整体开发目标，AI助手禁止私自开发文档中有但用户还未让AI助手开发的内容，在用户要求你制作的时候你做就行，文档仅供AI助手浏览以了解整体目标。
10. today.md中为进程表，请AI助手根据目前开发进程自行确认完成进度
11. 所有文档必须使用中文撰写。

## 项目特殊规则

1. 测试账号体系：test1-test4 为测试账号，数据不落盘、隐身于正式玩家。开发测试时优先使用测试账号，避免污染正式数据。
2. 房间系统与登录系统解耦：修改房间系统时不得影响登录、在线状态、游客入口等无关逻辑。
3. 数据持久化文件存放在 data/ 目录（users.json、achievements.json、game-records.json），代码更新不删除数据文件。
4. 服务器端做数据校验：正式玩家数据写入 JSON 文件前，必须检查 socket.isTest 是否为 true，测试者数据跳过写入。
5. 联机功能测试必须开两个窗口（普通 + 隐身窗口 Ctrl+Shift+N），分别用不同账号登录。
6. 修改 server.js 后必须重启服务器（Ctrl+C → node server.js），前端修改后浏览器强制刷新（Ctrl+Shift+R）。

## 错误编码规则

- 错误编码格式：A000、A001、A002……依次递增。
- 每个错误在 Dev/error.md 中记录：错误编码、错误现象、错误原因、解决办法、如何避免。
- 开发前必须阅读 error.md，避免重复犯错。

## 版本号规则

- 当前版本：0.1（联机版快艇骰子开发中）
- 每次修改后版本号 +0.1（如 0.1 → 0.2）
- 在 Dev/log.md 中记录版本号、修改文件、修改原因

## 协作模式

1. 用户是项目的唯一决策者，所有设计最终由用户拍板。
2. AI助手的角色：梳理思路、分析可行性、提供备选方案、编写代码。
3. AI助手不得在用户未确认的情况下擅自添加新功能。
4. 当涉及精确数据（概率模拟、数值平衡等）时，需要在可靠的模拟逻辑下进行。
5. 所有代码修改必须给出完整可复制的代码块，不得只描述思路。
6. 代码风格：中文注释、console.log 调试风格、保持现有代码结构。
