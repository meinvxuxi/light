> 本文档记录成就系统的全部通用设计与实现规则。具体成就列表见 cj1.md。

## 一、成就系统定位

成就系统是游戏室的"荣誉墙总管"。各游戏在关键时刻触发成就信号，成就系统负责判定、存储、播报、展示。成就系统与游戏逻辑完全解耦。

---

## 二、品质分层

所有成就按以下品质分类：

| 品质 | 图标 | 稀有度定位 | 触发频率参考 |
|------|------|-----------|------------|
| 🥉 普通 | 🥉 | 高频触发，纪念性 | 每局都可能触发 |
| 🥈 稀有 | 🥈 | 需要一定技巧或条件 | 每3-10局触发一次 |
| 🥇 史诗 | 🥇 | 高难度，综合策略+运气 | 每10-50局触发一次 |
| 👑 传说 | 👑 | 极稀有，百局一见 | 每50局以上触发一次 |
| 💀 隐藏 | 💀 | 整活/意外/天谴，条件不公开 | 不定，看运气 |
| 🔄 可升级 | 🔄 | 同一成就多个档位，跨品质 | 随档位提升递减 |

## 三、架构设计：集中式成就总管

### 核心原则
- 各游戏只负责"触发信号"，成就总管负责"判定与记录"
- 游戏代码中只在关键时刻调用 `triggerAchievement(playerName, achievementId)`
- 成就总管检查触发条件、判断是否已获得、更新数据、决定播报方式

### 数据流
```
游戏逻辑检测到事件
    ↓
调用 triggerAchievement(playerName, achievementId)
    ↓
成就总管检查：
  1. 该玩家是否是测试者（是则跳过）
  2. 该成就是否已触发过（可重复成就则累加）
  3. 是否满足品质升级条件（可升级成就）
    ↓
更新内存数据 + 写入 JSON 文件
    ↓
决定播报方式并广播
```

---

## 四、数据存储结构

### 存储文件
```text
data/achievements.json   # 正式玩家成就（荣誉墙读取）；仅在 PERSIST_ACHIEVEMENTS=true（正式版）时读写
```

### 存储说明
- 正式玩家：仅当服务器 `PERSIST_ACHIEVEMENTS = true`（正式版）时写入 achievements.json；开发/测试期 = false 时只存内存、重启即清空；
- 测试账号（测试者1~4）：**永远只存内存**（重启即刷新），不落盘任何文件；
- 开发者工具生成的"模拟结算对局"（mock 局）不判定、不写入任何成就；
- 更新代码时不得删除 data/ 目录；服务器重启时按 PERSIST_ACHIEVEMENTS 决定是否从文件读回。

### 数据结构
```json
[
  {
    "achievementId": "yahtzee_first_roll",
    "playerName": "玩家1",
    "count": 1,
    "firstTime": 1716153600000,
    "lastTime": 1716157200000,
    "highestTier": 2
  }
]
```

### 字段说明
| 字段 | 类型 | 说明 |
|------|------|------|
| achievementId | string | 成就唯一标识 |
| playerName | string | 获得成就的玩家名 |
| count | number | 触发次数（可重复成就累加） |
| firstTime | timestamp | 首次触发时间 |
| lastTime | timestamp | 最近触发时间 |
| highestTier | number | 最高品质档位（可升级成就用，1=普通 2=稀有 3=史诗 4=传说） |

## 五、播报机制

### 按信息差分类
| 类型 | 定义 | 播报时机 |
|------|------|---------|
| 无信息差成就 | 触发条件不涉及游戏中的隐藏信息 | 触发后立即播报 |
| 有信息差成就 | 触发条件会暴露场上隐藏信息（如回声链猜对自己的词） | 触发时仅自己可见，游戏结束后在复盘页统一展示 |

### 播报方式
1. **全屏播报**：半透明横幅在游戏界面角落或顶部短暂浮现（约3秒），不遮挡核心操作区，自动消失
2. **消息栏播报**：在聊天/消息栏发布系统消息："🎉 [玩家名] 获得了成就 [成就名]！"
3. **仅自己可见**：有信息差成就触发时，只向触发者推送提示

### 播报规则
- 所有成就至少触发消息栏播报
- 稀有及以上品质额外触发全屏横幅播报
- 隐藏成就在游戏中不公开播报，游戏结束后统一展示

## 六、荣誉墙展示规则

### 页面位置
荣誉墙作为独立页面（`achievements.html`）或主页功能入口之一。

### 展示规则
- 未触发过的成就**一律不显示**
- 触发过的成就显示：成就名、成就品质颜色标识
- 每个成就下方列出获得该成就的玩家名单，包含：玩家名、触发次数（xN）、首次触发时间、最近触发时间
- 可升级成就按品质档位展开显示各档位获得者

### 展示格式示例
```
🎰 一发入魂 [👑 传说]
  ├── 玩家1 x1（首次：2026-05-15）
  └── 玩家3 x2（首次：2026-05-18，最近：2026-07-01）

💀 世一炸 [🔄 可升级]
  ├── 🥉 2连击：玩家2 x3
  ├── 🥈 3连击：玩家2 x1
  ├── 🥇 4连击：（暂无）
  └── 👑 5连击+：（暂无）
```

## 七、测试者规则

- 测试者（test1-test4）触发的成就**不落盘任何文件**：只存服务器内存，程序重启即清空（与"最后上线时间"等内存态数据一致）
- 测试者的成就在荣誉墙**不可见**于正式玩家（仅测试账号自己登录荣誉墙时可看到自己的测试记录，带"测试"标记）
- 测试面板（test-panel.html）提供"一键触发成就"功能，用于测试成就判定和播报逻辑
- 测试面板还提供"重置测试成就"功能，只清空 `data/test-achievements.json`

### 服务器端实现要求
- 正式玩家（玩家1~4）→ 仅在 `PERSIST_ACHIEVEMENTS=true` 时写 `data/achievements.json`（开发期只内存）
- 测试账号（测试者1~4）→ 只存内存，不写任何文件
- mock/模拟结算对局（开发者工具生成）→ 不判定、不写入任何成就
- 荣誉墙数据源：get_achievements 返回 list（正式）与 testList（测试，仅测试账号端显示）

## 八、可升级成就机制

### 设计原则
- 同一成就存在多个品质档位（如2连击=普通、3连击=稀有、4连击=史诗、5连击+=传说）
- 触发低档位后，高档位仍可继续触发
- 荣誉墙展示时按品质档位展开，各档位独立记录获得者
- 已获得的档位不会因重复触发而覆盖

### 升级判定
```javascript
// 示例：连击成就的档位判定
if (streak >= 5) tier = 4;      // 传说
else if (streak >= 4) tier = 3; // 史诗
else if (streak >= 3) tier = 2; // 稀有
else if (streak >= 2) tier = 1; // 普通
```

---

## 九、可重复累积规则

- 所有成就默认可重复触发，触发次数累加
- 荣誉墙显示时标注 `xN`（N为触发次数）
- 首次触发时间和最近触发时间分别记录
- 某些特殊成就（如隐藏彩蛋类）可设置为不可重复，由具体成就定义决定

## 十、与游戏的集成方式

### 游戏中插入触发点
```javascript
// 示例：快艇骰子中投出快艇时
if (new Set(dice).size === 1) {
  socket.emit('trigger_achievement', {
    achievementId: 'yahtzee_roll',
    playerName: myName
  });
}
```

### 成就总管监听
```javascript
socket.on('trigger_achievement', ({ achievementId, playerName }) => {
  triggerAchievement(playerName, achievementId);
});
```

- 白色文字，金色边框

### 荣誉墙页面
- 按品质分组展示（传说到普通从上到下）
- 每个成就是一张卡片
- 卡片内显示成就名、触发条件简述、获得者列表
- 未触发成就完全不显示

## 十二、协作模式

1. 具体成就的触发条件、品质归属、成就名由用户定稿（见 cj1.md）
2. AI助手负责实现成就总管的代码逻辑
3. 修改成就系统代码时，不得改动游戏本身的核心逻辑
4. 新增游戏接入成就系统时，只需在游戏代码中插入触发点，不需修改成就总管

## 十三、快艇骰子本期落地约定（2026-09-05 确认）

### 判定时机
- 能即时判定的成就：在掷骰/提交瞬间即时触发（实时播报）
- 只能整局判定的成就（总分阈值、跨玩家比较）：在 `phase='finished'` 结算时统一判定
- 结算播报：整局结束广播"本局成就汇总"（成就名 + 达成的玩家们），即时成就也会出现在汇总里

### 重复快艇 +100 规则（含在本期实现）
- 玩家已填写过"快艇(yahtzee)"格（该格已有值，含 0 或 50）后，**之后每次再投出快艇**，该玩家总分额外 +100（记入玩家 `yahtzeeBonus`，随总分结算）
- 首次快艇若填入其他格（未填快艇格）不计 +100
- 总分口径 = 上区小计 + 上区奖励35（若≥63） + 下区小计 + yahtzeeBonus

### 葫芦兄弟判定定义
- "葫芦点数完全相同" = 三元点数 与 对子点数 都相同才算同一组合（例：A=2-2-2-5-5 与 B=5-5-5-2-2 不算相同）
- 整局内同一组合的玩家 ≥2 即解锁（即时/结算双保险）

### 隐藏成就
- "认真的吗？（总分<100）"：**一律算作非故意**，不做额外判定，只在结算汇总展示（不实时播报）

### mock 局
- 开发者工具的"🧪 直接结算"生成的对局是 mock 局，**不判定、不写入任何成就**
